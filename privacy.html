Privacy Policy

AI Calendar Update · last updated 17 October 2026

1. Summary

AI Calendar Update ("the assistant") is a personal tool operated by a single user for their own use. It is self-hosted on a private server, authorised only against the operator's own Google account, and not offered to any other person. Google user data accessed by the assistant is not shared with, sold to, or disclosed to any third party.

2. Who this applies to

This policy covers the assistant's processing of Google account data belonging to the operator. There are no end users other than the operator. No data is collected from visitors to the app's public website; those pages are static and contain no analytics, advertising, cookies, or tracking scripts.

3. Google permissions requested

The assistant requests exactly two OAuth 2.0 scopes. No other scope is requested.

Scope Capability How it is used
https://www.googleapis.com/auth/calendar Calendar: view, edit, create, and permanently delete events Creating appointments at the operator's request; setting default reminders on events the assistant creates; reading scheduled events to answer questions such as what is on my calendar this week. Event deletion is used only to correct events the assistant itself created in error, and always in response to an explicit instruction.
https://www.googleapis.com/auth/gmail.readonly Gmail: read only Reading and searching the operator's mail to summarise it or answer questions about it. This scope cannot send, delete, label, or modify messages.

4. How data is stored

  • OAuth credentials, including refresh tokens, are stored on the operator's private server in a per-profile directory with filesystem permissions limited to the service account that runs the assistant. They are not written to source control, logs, or backups outside that server.
  • Conversation history is retained locally on that server so the assistant can retain context across messages.
  • Calendar and mail content is read into working memory only to answer the operator's request. It is not copied into any external database or long-term store.

5. Sharing and third parties

Google user data accessed by the assistant is not shared with, sold to, licensed, or disclosed to any third party. There are no third-party analytics, advertising, or tracking services in the assistant or on its public website.

Data is transmitted only to Google's own API endpoints (googleapis.com) to perform the calendar and mail operations described above.

6. Retention and deletion

  • Authorisation may be revoked at any time from the Google account permissions page, which immediately invalidates all tokens held by the assistant.
  • Stored conversation history can be deleted by the operator at any time, and is removed when the operator's server profile is deleted.
  • Google account data itself remains under the operator's control in their own Google account and is deleted according to Google's own retention policies.

7. Model processing

Requests handled by the assistant may be transmitted to a third-party language model provider in order to generate a response. Only the conversation context needed to answer the request is sent. The operator has not authorised the assistant to transmit data for model training, and does not knowingly do so.

8. Security

The assistant is reachable only through the operator's private messaging account, and is protected by that account's authentication. Google credentials are held with restricted filesystem permissions. No claim of absolute security is made.

9. Changes to this policy

Any material change to the scopes requested or the data handling described here will be reflected on this page before the change takes effect.

10. Contact

The operator can be contacted through the messaging account used to reach the assistant.
