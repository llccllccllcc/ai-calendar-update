AI Calendar Update

Personal calendar assistant · single-user deployment

What this is

A personal assistant for a single user. It connects to one Google account so the operator can create and read calendar entries and check their mail by sending it a message on Telegram. It runs on a private server, and it is not a service offered to anyone else.

What it can access

Two Google permissions, and nothing beyond them:

  • Google Calendar — read, edit, and create events. Used to add appointments on request, including reminders on new events, and to report what's scheduled.
  • Gmail — read only. Used to summarise and search mail. It cannot send, delete, or modify messages.

How the data is handled

  • Single user. Only one Google account is authorised. There are no other users and no shared access.
  • Self-hosted. The assistant and its credentials run on a private server. OAuth tokens are stored locally in that server's private profile directory with filesystem permissions restricted to the service account.
  • No third-party transfer. Google user data is not sold, shared, rented, or provided to any third party, advertiser, or analytics service. There is no analytics or advertising code on these pages or in the assistant.
  • Limited retention. Data is read on request to answer a message. Conversation history is retained locally so the assistant retains context between messages, and is not retained by any external party.

Revoking access

Access can be withdrawn at any time from the Google account permissions page, which immediately invalidates the assistant's tokens. The relevant Google API services can also be disabled from the Cloud console, which invalidates them as well.
